# 企业落地指南

本仓库是 **合并前代码审核数字员工**（PHP / Python）。  
目标：在团队流水线里当 **初筛闸**，不是替代人工 Code Review。

---

## 1. 落地边界（先对齐预期）

| 级别 | 拦什么 | 建议 |
|------|--------|------|
| `--fail-on fatal`（默认） | 语法错误、括号不匹配等 | **企业默认门禁** |
| `--fail-on slow` | 再含 SLOW_SQL / SLOW_CODE | 性能敏感仓库可选 |
| `--fail-on any` | 再含命名 / LLM 等全部警告 | 过严，易被历史债淹没 |
| `--fail-on off` | 只出报告不失败 | 试跑 / 灰度 |

命名与慢代码当前多为 **警告**：报告里给人看，默认不挡合并。

---

## 2. 最小部署（单机 / 共享 runner）

```bash
cd /path/to/CodeReview
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
cp .env.example .env   # 填 MOONSHOT_*；可无 Key=跳过 LLM，规则引擎仍跑
# 编辑 projects.yaml，登记业务仓绝对路径 + 规范 md
make test              # 黄金用例必须绿
```

网页配置台（可选）：`make web` → http://127.0.0.1:8765

## 3. 业务仓 MR / PR 门禁（推荐）

在 **业务仓** CI 里调用本 Agent（共享机上的安装路径），不要复制一套规则。

### GitLab CI 示例

```yaml
code-review-gate:
  stage: test
  image: python:3.12-slim   # 或自建含本 Agent 的镜像
  variables:
    CODE_REVIEW_HOME: /opt/code-review-agent
  script:
    - cd "$CODE_REVIEW_HOME"
    - |
      bash scripts/ci_gate.sh \
        --project fm-app \
        --base "origin/$CI_MERGE_REQUEST_TARGET_BRANCH_NAME" \
        --head "$CI_COMMIT_SHA" \
        --fail-on fatal
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
```

说明：`projects.yaml` 里该项目的 `repo` 须指向 runner 能读到的业务仓 checkout（可用 CI checkout 路径覆盖——若路径与登记不一致，加 `--repo "$CI_PROJECT_DIR"`）。

CLI 已支持：

```bash
python -m code_review_agent review \
  --project fm-app \
  --repo /path/to/checkout \
  --base origin/pre \
  --head HEAD \
  --fail-on fatal
```

### GitHub Actions 示例

```yaml
- name: Code review gate
  run: |
    bash /opt/code-review-agent/scripts/ci_gate.sh \
      --project fm-app \
      --repo "${{ github.workspace }}" \
      --base "origin/${{ github.base_ref }}" \
      --head "${{ github.sha }}" \
      --fail-on fatal
```

## 4. 本 Agent 仓库的自检门禁

防止规则回退误报：

```bash
make hooks-install   # git config core.hooksPath hooks
make test            # 或 python -m code_review_agent self-check
```

- GitHub：`.github/workflows/self-check.yml`
- GitLab：`.gitlab-ci.yml`
- 可选：`pre-commit install`（`.pre-commit-config.yaml`）

---

## 5. 退出码约定（给 CI）

| 码 | 含义 |
|----|------|
| 0 | 通过门禁 |
| 1 | 未通过门禁（fatal / slow / any 触发） |
| 2 | 配置错误、git 错误、审核过程 error |

报告仍会写入 `reports/{project}/{date}/`，便于人工打开。

---

## 6. 企业验收清单

- [ ] `make test` 全绿
- [ ] `projects.yaml` 已登记目标业务仓，路径在 runner 可读
- [ ] 试跑一条真实 MR：`--fail-on fatal` 对「故意语法错误」分支 exit 1
- [ ] 试跑已知误报样例（数组键 `update`、HTTP DELETE、预取+foreach）：**不报 SLOW_SQL**
- [ ] LLM Key 可选；无 Key / 网络失败时仍出规则报告
- [ ] 团队约定：报告为初筛，安全与业务逻辑仍要人审
- [ ] （可选）升 `--fail-on slow` 前先灰度一周看噪声

## 8. 飞书推送（自定义机器人）

1. 群里添加自定义机器人，记下 Webhook、签名校验密钥、自定义关键词（如 `审核推送`）。
2. 写入本机 `.env`（**勿提交 git**）：

```bash
FEISHU_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxxx
FEISHU_WEBHOOK_SECRET=你的签名密钥
FEISHU_WEBHOOK_KEYWORD=审核推送
FEISHU_NOTIFY=auto
```

3. 自测：`python -m code_review_agent feishu-test`  
4. 正式：CLI `review` / 网页生成报告结束后，若配置了 URL 且 `FEISHU_NOTIFY` 非 `off`，会自动推摘要（含关键词与本地报告路径）。

关闭推送：`FEISHU_NOTIFY=off` 或 CLI `--notify-feishu off`。


- PHPStan 未挂进 LangGraph 主流程（可用 skill `analyse-with-phpstan` 人工补）
- 网页审核为大 diff 同步阻塞，无队列
- 命名警告对历史债吵——默认不进 hard gate
- webhook / pre-receive 服务器钩子仍需按业务 Git 平台再包一层（CLI 已可被 CI 调用）

达到上文验收清单即可视为 **可企业初筛落地**；要做「零人工硬门禁」还需继续压命名噪声与安全规则。
